# ml/ — Predictive Fault Engine (Phase 2)

Phase 2 predictor: detects precursor patterns before faults manifest, and estimates time-to-impact.

**Architecture:** Two LightGBM models (offline, no neural nets):
1. **Classifier** — precursor probability (0–1) for every monitored node/interface
2. **Regressor** — estimated seconds until impact event (e.g. down event, drop burst)

Features are computed from a sliding window of interface metrics (utilization, latency, jitter, packet loss) and event history. Models train on labelled windows generated by fault injection (see below).

## Running end-to-end

**Prerequisites:** simulator and backend running (see root `README.md`).

> **Do steps 1–2 before starting the service, Docker included.** `ml/models/`
> is git-ignored — on a fresh clone (or a fresh `docker compose up`) it's
> empty, and `Predictor.__init__` (`ml/service/predictor.py`) fatally raises
> `FileNotFoundError` if `classifier.txt`/`regressor.txt`/`features.json`
> aren't there. Skipping this step means the `ml` container just crash-loops.

```bash
# 1. Generate labelled training data (simulates 3 scenarios × 6 nodes, ~30 min)
python -m ml.dataset.generate

# 2. Train both models (saves to ml/models/)
python -m ml.train
# Expected: "classifier held-out AUC: 0.NN", "regressor held-out MAE: NN.Ns"

# 3. Start the live prediction service (listens on :8200)
python -m ml.main
```

Then verify it's alive:

```bash
curl localhost:8200/health
curl localhost:8200/predictions
curl localhost:8200/predictions/pe-east
```

## API reference (`:8200`)

| Endpoint | Description |
|---|---|
| `GET /predictions` | Current precursor probability + estimated time-to-impact for every node/interface with a warm buffer |
| `GET /predictions/{node_id}` | Current predictions for one node |
| `WS /ws/predictions` | Pushes a prediction update every time a node/interface's buffer is recomputed |
| `GET /health` | Liveness |

Interactive docs: **http://localhost:8200/docs**

## Design & training data

Full design rationale (feature engineering, model choice, label math, performance targets):
[`docs/superpowers/specs/2026-07-13-phase2-predictive-fault-engine-design.md`](../docs/superpowers/specs/2026-07-13-phase2-predictive-fault-engine-design.md)

**Generating labelled data:** Inject a fault via the simulator's `/faults` endpoint (see root `README.md` for examples). The simulator ramps the fault gradually over `ramp_seconds` (the precursor signature). Every event row in `data/drishti.db` carries `details.fault_id`/`details.scenario` — ground-truth labels for free. `ml.dataset.generate` runs this harness end-to-end.
